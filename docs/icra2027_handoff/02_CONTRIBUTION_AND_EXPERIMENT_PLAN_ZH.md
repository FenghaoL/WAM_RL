# 新实机结果后的取舍：主线、证据与补实验优先级

本文件更新自用户最新反馈：共同13个初始化场景首次rollout中，圆柱SFT为1/13，基本纠正为5/13，vidext为6/13，基本full与未来视觉延伸full接近；适配器新数据为HIL v3。它是执行建议，不把待做对照列为已实现贡献。作者正文入口见[论文骨架](00_PAPER_SKELETON_ZH.md)。

## 1. 现在已经能说什么

用户进一步确认：每个模型在共同13个初始化场景的第一次rollout中，SFT为1/13（7.7%），基本full为5/13（38.5%），vidext为6/13（46.2%）。对应相对SFT增加30.8和38.5个百分点。这是值得继续验证的改善信号；同时观察到抓取降落偏差后的定向调整和插偏后向孔移动。

首次rollout提供了条件权重一致的比较口径，但它是在本次讨论中回溯确定的，不应写为事先注册。实际checkpoint step及每个场景的成功/失败向量尚未提供，不能从三个总数推算配对显著性。1/13对应用户此前baseline汇总，提交前一并核对确实是相同首次试验集合。

此前7/17–9/17是两个模型各自含额外重复的结果，不是成功判定不确定。额外重复不丢弃，可作为补充完整记录；逐模型全部rollout计数仍待登记。主表明确使用13个共同场景首次试验，不能把纠正模型更多重复与SFT首次试验放在同一分母口径比较。

13种初始化不是13个训练seed，单次/场景仍受随机动作和硬件时段影响。补测固定每条件每模型相同重复次数、交错顺序，保留所有成功与失败；在有逐场景记录后分析配对差异，重复条件以场景为簇处理。小样本不要用倍数放大叙事，优先次数和绝对差；两个纠正版本只差一次成功，不能声称等价或明确优势。

## 2. vidext与基本full：保留比较，不强行寻找正结果

**建议主配方可以选vidext，但在一个紧凑的机制表里保留基本full。** 主表用SFT与预先固定的主配方覆盖两个任务；圆柱机制表比较段内视频与未来视觉延伸。理由是监督范围本就是方法的一部分，读者会问额外设计是否必要。

两者成功率接近不使这个对照无价值。它约束了结论：目前不能证明延伸提高成功率，也不能证明两者等价；可能影响执行效率，也可能确实没有收益。只有样本量足够、预定义等价界限的设计才支持等价结论。

“更顺”先作为定性观察，选两项容易从录像稳定标注的指标：

- **恢复耗时**：从预定义偏差状态/首次明显失准到完成阶段；失败赋予固定超时T。另列成功轨迹耗时作为辅助，不只选择成功视频。
- **重复尝试次数**：一次下降接触后撤回算一次抓取/插入尝试；提前冻结定义，尽可能隐藏模型名标注。

不要直接用低分辨率录像的三阶差分声称jerk降低；噪声、帧率与滤波会主导指标。若有同频真实关节读回，可补报告经过同一处理的总运动量/速度变化，但更短动作并不自动更好，停住也会“平滑”。

若时间紧，两个现成模型的少量平衡复测比新训练第三个大模型成本更低。若最终仍只够主表，可在文字/补充材料报告该对照未显示清楚差异，不将vidext包装成已证实的主要收益来源。

## 3. 低成本平台与Video DiT：分别摆在什么位置

### 可写进论文的定位

- 实验平台：低成本SO101、双相机、视觉闭环、远程模型服务。
- 引言动机：精细接触任务需要处理部署中发生的位姿偏差，纠正数据覆盖这些困难状态。
- 结果：在当前设备与测试条件下观察到更高完成率及定向纠偏。
- 讨论：硬件状态、夹持偏差和控制等待可能影响表现，需要更系统的鲁棒性测试。

[LeRobot官方SO101文档](https://huggingface.co/docs/lerobot/en/so101)强调关节标定用于对齐物理位置与状态值。这支持核对标定的必要性，**不支持推断这台机械臂已经发生漂移或SO101普遍精度不稳定**。

前两天没有系统测量，“感觉更好”不能证明这次SFT真的退化。相机固定也不排除夹持姿态、物体/孔位置、照明、重置、策略采样、历史缓存及硬件状态变化。明天在同一时段交错执行SFT/纠正模型；记录checkpoint、stats、指令、推理步数、返回chunk、缓存重置和机器人标定标识。已有已知错误部署配置下的结果应分开记录，不能混入有效主表。

可在正式测试前做若干次相同非接触姿态的重复到位记录，比较指令与读回、固定相机中的末端位置。这只是诊断，不能测定全部接触精度。若维修或重新标定，将之后定义为新实验区块，并重新测两种模型。不要只在旧硬件条件测baseline，再在改善条件测新方法。

### Video DiT因果主张需要什么

“整体纠正配方有效”不能拆成“数据有效且Video DiT已经学会恢复动力学”。目前两种full都更新视觉分支，并使用video loss；它们只改变未来目标可用范围。

- 同full配方将video loss关掉：检验显式视频辅助目标，**不检验是否更新视觉参数**；动作梯度仍可能经过Video DiT。
- 同action-only配方冻结/更新Video DiT：更直接检验视觉参数可塑性，但必须保持Action DiT、原生路由等其余更新范围相同并记录精确参数名。
- 即使可塑性对照成功，仍不能单凭成功率证明模型学到了物理动力学或正确因果世界模型；那需要额外预测/反事实评估。

原来的小模块比较同时改变容量、学习率、anchor和视频目标，不能当作冻结视觉的干净证据。本轮作者材料不再展开这些探索，也不据此宣称所有轻量适配不可行。

## 4. 明天的优先级：机器人时间和三卡时间分别安排

| 优先级 | 实验 | 新GPU训练 | 真机负担 | 能支持的结论 |
|---|---|---|---|---|
| P0 | 当前cylinder平衡复测与逐trial登记 | 无 | 优先补共同条件，再同日交错复测 | 排除条件权重/日期偏差，巩固主结果 |
| P0 | power v3同配方训练与SFT对照 | 一次full | 每模型相同条件 | 第二任务的适用性 |
| P1 | 受控位置偏差的局部恢复图 | 无 | 约60次短试验起步 | 恢复范围，而非只展示几条成功视频 |
| P1 | 相同数据的接管内历史对照 | 一次full | 两模型相同完整/局部条件 | WAM上下文保留的机制价值 |
| P1/P2 | 原demo等预算继续训练 | 一次full | 与原SFT、纠正模型比较 | 区分额外优化与加入纠正数据 |
| P2 | video loss关闭 | 一次full | 同条件 | 视频辅助监督的作用 |
| P2 | 两现成full的恢复效率标注 | 无 | 录像可用时很小 | 检查“更顺”是否有可测依据 |
| P3 | 视觉分支冻结2×2及多个seed | 至少两次新增full | 多模型测试 | 视觉参数更新与辅助目标的关系 |
| 后续 | 等人工预算新demo vs纠正、第二轮交互、在线RL | 多次训练/采集 | 明显增加 | 数据效率、持续改进或奖励驱动学习 |

已有full运行约需一夜量级，不能把多个三卡任务都排成今晚完成。**今晚优先power；明天机器人测power，GPU若释放再做一个上下文对照。** 如果排期只能二选一，优先第二任务，再补无需训练的恢复图。若power尚未完成数据划分，先完成划分和加载验证；不要让形式上的“第二任务”污染测试。

若重视“改善是否仅因为训练更久”的审稿问题，demo继续训练是有用但非WAM专属的控制；若重视方法新意，上下文对照更直接。我的优先选择是第二任务 + 恢复图 + 一个上下文对照，随后demo继续训练。低成本机器人本身、更多训练次数和更复杂命名都不是新颖性的替代。

## 5. 可在一天内完成的恢复范围实验

先选择一个阶段：夹持圆柱后的孔口对准，减少从头抓取的耗时；如果抓取是主要瓶颈，再单独做抓取前阶段。不要把两种阶段混成同一个局部成功率。

1. 用固定物体/孔位定义中心，以及左右前后4个方向；为每方向设置近、远两档实际可重复偏移，共中心加8种条件。幅度根据孔尺寸和可安全复现的范围先做开发试验确定，然后冻结，不按模型胜负挑幅度。
2. 每条件每模型先做3次，SFT与选定纠正模型交错执行，总计54次；加少量参考条件约60次。时间允许增至5次/条件。每格3次只能形成初步范围图，不能提供精确成功概率。
3. 使用相同夹持方式、末端高度、姿态、任务指令和真实可获得的历史初始化协议。可以统一从局部重置后清空缓存再积累固定观察前缀；不伪造接管前历史。该协议单独标为local recovery，不替代完整任务部署协议。
4. 记录方向、测得偏移、重复编号、模型/step、session、最大时长、是否接管、成功与失败阶段。抓取/插入阈值和尝试定义预先固定。
5. 画方向×幅度成功次数图，以及恢复耗时图。若纠正模型只改善某些方向，结合训练纠正方向覆盖讨论；未见方向优势不能说恢复半径普遍扩大。

[JUICER](https://imitation-juicer.github.io/)在模拟装配中使用瓶颈附近的纠正数据扩展，支持聚焦这些状态的研究动机。这里提出的54次真机协议是针对本项目的预算设计，不是照搬其验证过的样本量或方法。它测试外部初始偏差，不是故意制造机械故障的实验。

## 6. 有训练预算时的科学对照

### A. 上下文截断：最贴近当前WAM问题

同一个cylinder SFT起点、同一HIL-v2划分、同batch12/lr1e-5/3285步、相同video目标，仅改变训练HUMAN窗口的跨接管历史规则。部署全部history6，使用相同缓存重置。不用旧数据或无记忆SFT代替。

已有 `runs/icra2027_cylinder_controls/configs/full_context_truncated.yaml` 以**基本full**为父配置，应与基本full比较。若希望以vidext作主机制对象，可复用生成器另生成隔离目录：

```bash
PYTHONPATH=src:. /home/fenghao/miniconda3/envs/ahawam/bin/python \
  scripts/so101_pipeline/paper_experiments/prepare.py controls \
  --base-config runs/ovcr_adapter_cylinder_hil_v2_full/configs/p1_full_balanced_video_hilv2_vidext.yaml \
  --run-root runs/icra2027_cylinder_vidext_controls \
  --variants context_truncated video_off
```

这是建议入口，本轮没有执行生成或启动。先检查父manifest、数据加载，再smoke。生成器拒绝覆盖已有目录。两项都生成不等于都需要立即训练。验证窗口保持固定；如果比较的是历史构造整体（含时间位置），论文也应这么命名。

### B. 原demo继续训练：隔离额外优化

从同一个任务SFT出发，只用原demo训练3285步，global12，lr1e-5，其余骨干、优化器与推理固定。应通过原full训练器的数据配置实现真正demo-only，不能把旧纠正目录换成demo后仍保留HUMAN筛选。

与纠正训练相比，这个控制拥有更多demo抽样但没有额外纠正，是**同优化预算**对照。它不能回答“同等额外人工时间下新demo与纠正哪个更好”；后者需要新采demo并记录人工监控、接管和重置总成本。[IWR](https://arxiv.org/abs/2012.06733)已比较干预数据与等量非干预示范，故数据预算比较很有依据，但不能把本项目不同预算的实验称为其复现。本轮尚未新增demo-only配置。

### C. 视觉分支更新×视频loss：更强但更费时间

先用基本full、相同数据范围做以下2×2；各组从同SFT出发，原生路由/Action DiT更新范围固定：

| | video loss=0 | video loss=1 |
|---|---|---|
| Video DiT可更新 | 新控制，可复用video_off | 已有基本full |
| Video DiT冻结 | 新控制，需修改训练器 | 通常与左格动作更新等价，需先审计计算图 |

若视频损失仅作用于已冻结参数，右下格不会对可训练策略提供额外梯度，不能当作第四个有效独立机制。需检查是否还有可训练共享表征接收视频梯度；报告梯度路径。重点比较上行有/无视频目标，再比较左列冻结/可更新视觉。

当前 `v2_experiments/run.py` 的 `FullTrainer` 明确拒绝 `freeze_video_dit=true`。不能只改YAML就声称已有冻结对照入口；需要新增受控训练范围、检查参数集合与梯度、做数据和两步训练验证。该项本轮只制定设计，不修改正在使用的训练器。

## 8. 论文的竞争力与后续路线

当前最可信的贡献组合是：带记忆WAM的人类纠正训练协议、接管边界与监督范围处理、低成本真机上的两任务与恢复机制分析。仅“对WAM做DAgger”创新有限；[SIRIUS](https://roboticsproceedings.org/rss19/p005.pdf)已有部署纠正与加权BC，[Sirius-Fleet](https://ut-austin-rpl.github.io/sirius-fleet/)还将视觉世界模型用于交互部署监测。因此，应突出本模型的时序输入/生成目标适配，并通过同数据对照验证，不能声称首次把世界模型和接管相结合。

若第二任务也改善且上下文/恢复图支持解释，论文会比目前只有单任务汇总更完整。如果上下文无差异、视频延伸也无明确差异，仍可写诚实的系统与实证研究，但方法贡献较弱，不能靠隐藏无差异对照补强。没有可靠方式承诺ICRA接收概率。

后续值得投入：同人工预算的纠正效率曲线、第二轮部署更新、多个seed及跨session硬件状态复测；若加在线RL，需要reward、实际transition、探索、接管处理及独立BC+RL对照。现在为了名称赶一个RL头不比补这些证据更有说服力。轻量视觉适配可留作未来方向，不必恢复旧模块结果表。
