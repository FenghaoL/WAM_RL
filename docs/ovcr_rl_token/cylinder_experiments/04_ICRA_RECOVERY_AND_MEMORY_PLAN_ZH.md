# 9 月 15 日截止前：局部恢复数据、历史 KV 与 OVCR 的实验决策

核查日期：2026-09-11。本文针对当前 **cylinder** 实验；不能把这里的数据统计直接套到 power-adapter。结论是：继续已启动的无记忆 SFT，优先采集有结构的局部恢复示范，先验证数据是否有效，再检验 OVCR 的额外收益。剩余时间内不把新建在线 RL 系统设为投稿前置条件。

这是研究与排期建议，尚未获得新恢复数据或新真机成功率。本文没有启动新训练、改变正在运行的队列或修改部署配置。历史统计见 [审计 JSON](memory_coverage_audit_20260911.json)。

## 1. 你的 memory 怀疑有代码与数据依据，但尚未证明因果

### 1.1 训练并不要求采集时保存 KV

实际路径是：历史观测图像 → 用当前模型重新计算历史 video KV → 当前 video 特征读取历史 → OVCR → Action DiT → action loss。

- [robot_video_dataset.py](../../../src/ahawam/datasets/lerobot/robot_video_dataset.py) 的 `get_video_history_valid_len_for_index` 按逻辑 episode 边界决定能读多少历史。
- 当前 `num_frames=49`、`global_sample_stride=1`，历史间隔为 `(49-1)*1=48` 个原始 tick。15 Hz 下约 3.2 秒。样本起点在逻辑 episode 内的位置为 `i` 时，有效历史数是 `min(6, floor(i/48))`。
- [hil_human_only_dataset.py](../../../scripts/so101_pipeline/hil_human_only_dataset.py) 把每个连续 HUMAN 接管段映射成独立逻辑 episode。因此，即使原始 rollout 保存了接管前的 POLICY 图像，当前 HUMAN loader 也不会把它们纳入历史。
- [ahawam.py](../../../src/ahawam/models/wan22/ahawam.py) 的训练路径用 `torch.no_grad()` 重新编码历史，再 detach KV；历史不接收梯度，却仍影响当前预测与 adapter 梯度。

所以问题是**历史上下文被逻辑片段边界截断，以及训练/部署的历史分布不同**，而不是原始数据没有保存中间 KV 文件。

### 1.2 cylinder 的实际分布

以下由冻结的 HUMAN manifest 段长和 demo `meta/episodes.jsonl` 计算，已核对总帧数；统计的是所有逻辑样本起点，不是训练日志中已经实现的每个 batch。来源重采样、DDP 补齐、随机 action offset 等不包含在这张表里。

| 有效历史数 | Demo 训练起点 | HUMAN 训练起点 |
|---|---:|---:|
| 0 | 4,512（22.9%） | 2,122（88.7%） |
| 1 | 4,512 | 195 |
| 2 | 4,505 | 70 |
| 3 | 3,936 | 6 |
| 4 | 1,864 | 0 |
| 5 | 315 | 0 |
| 6 | 64 | 0 |
| 合计 | 19,708 | 2,393 |

HUMAN 训练有 77 段，最长 150 帧。49 帧完整未来窗口只有 **271 个起点，约 11.3%**，其余起点不能按现有完整窗口规则获得 video loss。这个 271 恰好也等于有历史的起点数，因为两个规则都涉及 48 帧；**它们不是同一组起点**：有历史在段尾，完整未来窗口在段首。

这解释了两个潜在困难：纠正样本以冷启动为主；大部分纠正样本只有 action 监督。与此同时，demo 也有 22.9% 冷启动样本，所以不能说原模型完全没有学过无历史条件。

此外，HUMAN 自然帧占比只有 10.8%。1:1 来源混合在 demo 完整覆盖一遍的预算下，会使旧 HUMAN 起点平均重复约 `19708/2393=8.24` 次。反复训练同一小片偏差，不能扩充空间覆盖。

### 1.3 关闭历史值得做，但不是修复效果的保证

从 AHA pretrained 重新训练 `num_history_frames=0` 的任务 SFT，再从它出发训练纠正模型，是合理的匹配实验。只在原 history-6 权重部署时关历史，不能替代这个 baseline。

无历史仍保留当前观测、当前 Video DiT、OVCR 和 Action DiT，不等于完全不看视频。对于当前双相机足以判断相对位置的局部对准任务，移除长期上下文可能降低短示范的训练难度。这是待检验的推理。遮挡、接触状态、运动方向或任务阶段依赖历史时，它也可能降低完整任务性能。

“不使用历史”还涉及当前训练分支的 temporal position 处理，不能在没有额外控制时，把所有差异都归因于 KV 内容本身。部署至少须核对最终解析的 `model.num_history_frames=0`，每次人工重新摆放物体后重置 episode/cache，并确保其余相机、归一化、动作 chunk、推理步数和控制参数一致。当前读取的 `settings_dagger.yaml` 和 `deployments/cylinder_v1_sft.yaml` 都仍配置为 6，不能原样用于无记忆对照。

如果 no-history 退化，另一条路线是**保留接管前观测作为 context，只在接管动作上计算监督**。观测来自 POLICY 并不意味着把 POLICY 动作当专家标签。需要新建上下文索引，保持原始时间与连续性，不跨 episode/重置/丢帧错误拼接；然后按部署式 prefill 做上下文预热。使用当前权重重算上下文能避免旧 KV 随权重变化而过时。现有 loader 没有实现这个行为。

这类状态重建问题与 [R2D2 对 recurrent replay 中表征漂移和状态过时的研究](https://willdabney.com/publication/r2d2/)有概念联系；RNN 的实验不构成这里的 WAM 修复已经有效的证据。短期优先验证无历史，不同时增加这条数据管线。

## 2. V32 / Q32 / T4 都受历史影响

代码见 [ovcr_adapter.py](../../../src/ahawam/models/wan22/ovcr_adapter.py) 和 [mot.py](../../../src/ahawam/models/wan22/mot.py) 的 `build_layer_updated_cache`。三个模块的上投影零初始化，初始等价于绕过新增模块。

| 变体 | 当前实现 | 为什么受历史影响 | 主要限制 |
|---|---|---|---|
| V32 | 对 OVCR 的 decoded 特征做 rank-32 残差，只加到当前 action-readable V | decoded 由当前 K/V 路由得到；当前深层 K/V 已受历史条件化 | 能改内容，不能直接改 K 的检索位置；无法凭空恢复编码中丢掉的几何信息 |
| Q32 | 在原 OVCR query 投影前加 rank-32 残差 | 即使原始 query 来自当前观测，它查询的当前 K/V 仍受历史影响 | 学的是如何路由读取，不是独立的新视觉编码器 |
| T4 | 将 query/routed 特征压成 4 个内部 token，再解码并写入现有 K/V 位置 | routed/decoded 两条输入均依赖当前 K/V | 4-token 压缩可能损失细粒度信息；同时写 K/V 更灵活，也可能更难稳定训练 |

`action_video_read_mode=current_only` 只限制 action 直接读取的 video token 范围，**不保证这些 token 没有历史信息**。这些 adapter 不修改 planner 的历史缓存本体，但它们训练和使用的条件表示会随历史变化。

冻结大模型只是冻结权重，action loss 到 adapter 的梯度仍穿过 Action DiT。相比全量微调，参数与 optimizer 状态更少，不代表训练开销等于一个输出 MLP。现有 demo anchor 还需要额外 teacher 前向。

三者目前都是监督模仿学习模块，没有 reward、critic 或策略改进闭环。T4 的四个内部写入 token 也不是 RLT 的 RL readout。

**是否重跑：值得跑一个受控代表组，不值得今晚无条件把三组全部重跑。** 建议预先选 V32：结构最简单、修改范围较小，便于解释；这不是说现有实验已证明它最好。先在同一个无记忆 SFT 和同一批新恢复数据上比较普通微调与 V32。只有出现稳定收益且还有验证时间，才补 Q32；T4 放最后。不要把旧 history-6 adapter 权重直接接到重新训练的 no-history backbone，表征已改变，应重新零初始化。

## 3. 今晚的采集：局部恢复示范可行，但要覆盖真实失败

这更适合称为 **bottleneck recovery demonstrations / 局部恢复示范增强**。标准 DAgger 的关键是迭代执行当前策略并在其访问状态上获得专家标签；人工从预设偏差直接开始采集，是不同的状态采样方案。可以保留少量实际失败起点作为采样依据，但不需要每条示范都完整 rollout。

依据与边界：

- [DART，CoRL 2017](https://proceedings.mlr.press/v78/laskey17a.html)：通过专家示范中的噪声扰动增加偏离正常轨迹时的训练覆盖。支持“让示范包含恢复动作”的原则；你的人工重置不是 DART 的噪声估计算法。
- [JUICER](https://imitation-juicer.github.io/)：围绕装配瓶颈状态扩充局部纠正数据，并研究数据增强和策略组合；主要验证是仿真家具装配。与你的想法接近，所以既是依据，也是“局部补数据”本身不能宣称全新方法的原因。
- [IWR](https://sites.google.com/stanford.edu/iwr)：强调 manipulation bottleneck 的接管数据价值，使用 intervention/non-intervention 等比例采样，并比较等量完整示范。我们混合旧 demo 与新 recovery 的来源定义不同，不能把 1:1 宣称为该论文验证过的本任务最优比例。

先采少量 pilot 看当前相机是否真的能区分相反偏差。若孔口被遮挡、几何误差低于视觉分辨能力，或者抓持倾斜才是主因，重复横向平移不能解决观测不足。记录失败类型，避免把所有失败都叫“对不准”。

一个可执行的首批覆盖表如下；数量是工程起点，不是文献给出的最优样本数：

| 覆盖维度 | 建议首批分配 | 目的 |
|---|---|---|
| 孔周横向偏差 | 8 个方向 × 3 档距离 × 3 次独立重置，约 72 条 | 防止只学一个方向的推回动作 |
| 倾斜/抓持差异 | 约 16 条，改变 pitch/roll 或夹持偏心 | 覆盖“中心近但轴线歪”的失败；理想圆柱自身轴向 yaw 未必有意义 |
| 已对准状态 | 约 12 条，包括轻微误差和正常插入 | 防止一到孔口就额外横移 |
| 真实失败状态与衔接 | 另保留少量来自实际模型的接近失败，以及完整抓取到插入示范 | 检验人为重置分布是否覆盖真实接近阶段 |

三档距离根据孔隙、实际误差和可恢复范围定义并记录，不在未测量装配间隙时武断规定毫米值。覆盖时也变化孔板位置/朝向、抓持位置，避免只学固定关节姿态。原 demo 已存在跨 session 的孔板位置变化，新数据应兼容这些条件。

录制应包含“从偏差状态开始观察 → 必要时后退/抬起 → 对准 → 插入”的完整恢复过程。手动搬运、初始化、复位不能混成朝成功运动的专家动作标签。保存原始图像、状态、实际动作、时间戳和阶段标记；即使本轮关闭历史，原始上下文也值得保留。直接 teleop 数据应采用真实的 recovery 来源标签和合适 loader，不能为了复用 HUMAN-only loader 而伪造接管标记，或把未标记数据送进去后被全部过滤。

短片段可以只有 action loss；不要为了凑 49 帧而复制图像或长时间维持动作。完整 video 窗口需要真实连续、时间同步且监督有效。短片段还应统计有效 action mask：40 步 horizon 加随机 offset 会让段尾很多位置被 padding，名义 batch 12 不等于每步都有 12×40 个有效动作标签。

训练/验证按独立重置或 session/物理配置分组，先冻结划分；不把同一条轨迹的相邻帧随机拆到两边。测试既有覆盖范围内的新重置，也应保留未用于训练的偏差组合。只在人工摆好的孔口附近成功，不代表能从完整任务成功。

## 4. 最小实验矩阵：把数据收益与模型收益分开

定义 B6 为原 history-6 demo SFT，B0 为正在训练的 no-history demo SFT；D 为原 demo，H 为旧 HUMAN，R 为今晚新增 recovery。每个 history-0 模型均以 B0 为起点、部署 history-0。这里“旧 HUMAN”不包括自主失败动作标签。

| 优先级 | 实验 | 数据/训练 | 能回答的问题 |
|---|---|---|---|
| P0 | B0 与 B6 | 各自匹配的部署模式，不额外纠正训练 | 去掉历史是否保留完整任务能力 |
| P0 | B0 + full(D+H) | 已排队：旧 HUMAN 1:1 全量训练，合法窗口加 video loss | 同一份旧纠正数据在 no-history 下是否改善 |
| P1 | B0 + full(D+R) | 新 recovery 与 demo；先固定一套混合协议 | 覆盖新状态是否带来收益 |
| P1 | B0 + V32(D+R) | 同一数据、抽样预算和初始化，重新初始化 adapter | OVCR 方案是否有实际竞争力 |
| P2 | B0 + action LoRA 或通用 adapter(D+R) | 选择一个已可用且容量接近的实现 | 收益是否来自 OVCR 注入位置，而非任意小模块 |
| P2 | V32 的 anchor 或注入位置消融 | 一次只改变一个因素 | 解释保留能力/纠正能力的来源 |
| P3 | Q32、T4、重建历史 context | 在主结果成立之后 | 扩展机制分析 |
| P4 | 新建在线 RL | 独立交互与评估预算 | 奖励优化是否在同一 BC 起点上继续提升 |

不要把这张表理解成截止前必须全部跑完。最低有意义闭环是 B0、full(D+R)、V32(D+R)；已有 B6/旧 H 结果补充背景。若坚持 WAM 接口是方法贡献，普通 PEFT/输出监督 head 等位置对照的优先级高于把 Q32/T4 全部补齐。缺这个对照时应收缩接口优越性主张。

**现有 full 与 adapter 配方不构成纯位置消融。** 当前 full 使用 video loss=1、anchor=0、lr=1e-5；V32 使用 video loss=0、demo anchor=1、lr=1e-4。二者可作为完整训练方案比较，但不能把差值全归因于 OVCR。要隔离注入位置，应比较相同 action-only 目标、相同 replay/anchor 规则下的两个小模块；或者补 full action-only 与 V32 anchor-off 的控制。不同模块允许不同合理学习率，但须采用相同调参预算与验证规则，不在最终测试集挑配方。

新 R 数据默认建议先用 D:R=1:1，便于和旧流程衔接，并明确它只是起点。每个来源内部打乱、不放回遍历，来源耗尽再重新打乱循环。不能同时要求少数来源占 50%、完整覆盖多数来源且少数来源永不重复。若完整任务保留能力明显下降，再在开发集比较 D:R=3:1；不要一口气把所有比例铺开。若 R 已接近 D 量级，自然混合与 1:1 的差异会变小，应先统计新数据有效起点与有效标签。

沿用 3 卡、每卡 batch 4、accumulation 1，即全局 batch 12。固定 optimizer step 数以及各来源抽样数；同时报告有效 action 标签数、独立恢复起点数和墙钟时间。不要把不同来源 oversampling 的“四轮”视作等量数据。V32 可沿用 lr=1e-4/full lr=1e-5 做预先声明的起点，不把它们说成新 R 上已验证的最优值。以固定开发集选择预设 checkpoint，最终测试只用于报告。

旧 H 在首轮 D+R 对比中可先不加入，以清楚回答新采集是否有用；若加入，full 与 V32 必须用完全相同的 D/H/R 清单及权重。新 R 与旧 H 的对比若数据量和采集时间不同，只能称“新数据方案整体效果”；若要主张采集效率，须补等人工总时间（包括 reset/等待）的学习曲线。

### 关于历史的因果消融

已有条件可组成 B6 / B6+H / B0 / B0+H 的 2×2 对照，用“纠正训练前后成功率变化”的差异观察 memory 与短纠正的交互。但单个 seed、不同训练模式及位置编码分支限制因果强度。若只在 B0+新 R 看到了提升，不能同时宣布“历史问题修复”和“恢复数据更好”都被单独证实。

更强但不优先的诊断：在固定当前图像、状态、动作噪声和 timestep 下，比较真实历史、空历史、其他 episode 的历史对动作预测及 adapter 增量的影响。错误历史是人为分布偏移，只作敏感性诊断；它不能单独证明真实 memory 有害。重建上下文后只监督相同 HUMAN 动作，是比简单开/关 memory 更直接的训练控制。

## 5. 真机评估与停止条件

建议先用与最终测试隔离的约 12–16 个固定初始条件做开发筛选。若一个模型明显连正常插入/完整抓取都退化，停止扩展其三种 adapter 变体，先定位观测、mask、归一化与动作延迟。这个筛选不作论文显著性结论。

主比较尽量在预先冻结的同一组 **至少约 30 个独立测试条件/任务/模型** 上做配对评估；这只是时间受限的起点，不保证能检出小差异。按位姿条件分块、随机化模型执行顺序，避免光照、磨损、操作者状态与模型顺序混淆。边缘小提升需要更多重复；不能把 3–5 次成功当稳定改善。预算够时优先复验主对照的另一个训练 seed，而不是新增第三种模块。

至少分别报告：

1. 人工初始化在孔附近的局部恢复自主成功率，以及从抓取开始的完整任务自主成功率。
2. 成功次数/总次数和二项置信区间；配对条件比较用配对统计，不把视频帧当独立样本。
3. 完成时间、超时、人工接管次数；正式自主评估中一旦接管，该 trial 不能计作自主成功。
4. 按横向偏差、倾斜、抓持偏心分组的失败；初始范围及重置方式。
5. 人工采集总时间、恢复覆盖数量、训练 GPU 小时、推理耗时与暂停比例。

特别注意当前动作 chunk=8，在 15 Hz 下执行约 0.53 秒。接触附近的新信息能否及时进入下一次动作，对毫米级纠偏很重要。先记录当前端到端延迟与实际执行前缀；不能只凭 learner 更快就假定控制更快。缩短实际执行前缀可以成为单独的部署控制实验，但要所有方法一致，不能只给新方法更快的反馈。

## 6. 投稿前是否加真机 RL

长期看可以做；这次截止前，不建议把它变成必做项。之前在线 RL 文档是在“选择技术路线”的条件下优先推荐小输出 actor/critic；现在约四天的约束下，工程验证、采集、重复测试和论文改写成本改变了排序。

[RLT](https://arxiv.org/html/2604.23073v2) 先构造可供小策略使用的表征，再以参考动作和奖励训练 actor/critic；[HIL-SERL](https://hil-serl.github.io/) 包含奖励分类器、demo buffer、在线接管和逐渐减少干预的过程。[HALO-WA](https://arxiv.org/html/2607.04265v1) 已研究冻结 WAM、读取 latent 与参考动作的小 actor/critic。它公开在 arXiv 也应作为相关工作；不能把“WAM + 小 RL head”本身作为空白。

这些结果支持路线可行性，不保证本仓库已经有能稳定运行的在线系统。现有 V32/Q32/T4 也不是把 loss 名称改成 RL 就能完成迁移。直接用 action Q 更新 OVCR，需要梯度穿过 Action DiT；输出 actor 或以 latent 为动作的 Q 可以让 learner 不经过大 DiT，但后者还要验证 latent 的可控性。

只有同时满足以下实际条件，才考虑做一个独立 RL 扩展：局部任务重置稳定、奖励可靠、实际执行动作与 transition 对齐、在线 learner 和部署更新已经跑通，并且还留有至少一天做独立比较。首先在同一个 BC 起点上比较 BC-only 与 BC+RL，报告新在线环境步数/人工时间与学习曲线；补等额外人工预算的 BC，避免 RL 组只是获得了更多数据。

在线 RL 需要新策略与环境交互；小 actor 可以用 SAC 随机采样或 TD3 行为探索，不必给大模型权重加随机性。人类接管不是数学必要条件，但可用于启动与处理失败；必须记录真正执行的动作及干预，评估另算。今晚的恢复示范可做 BC warm start；没有 reward/terminal/next-observation 的片段不能直接当完整 RL transition。

若 9 月 12 日结束时闭环仍不能稳定更新，不再把 RL 放进这次主实验。这个日期是项目管理建议，不是算法定律。不要把临时出现的一次成功包装成 RL 有效。

## 7. 根据结果选择论文主线

| 最终证据 | 合理主线 | 应避免的主张 |
|---|---|---|
| 新 R 有效，V32 在多个任务/偏差条件优于普通适配，且保留原能力 | 面向 WAM 精细操作的接口适配；局部恢复数据与历史匹配为训练协议 | 未比较其他接口却声称 OVCR 最优；称监督模块为 RL |
| V32 成功率与 full 相当，但明显减少可训练参数/显存，并有保留能力优势 | 参数高效的 WAM 局部恢复适配，报告实测成本与性能折中 | 参数少就宣称训练墙钟更快；只凭接近的点估计宣称等效 |
| no-history/full(D+R) 有效，V32 没有额外收益 | 局部恢复数据/上下文一致性的系统与实证研究 | 把数据收益归因于 adapter；忽略 DART/JUICER/IWR 的接近思路 |
| memory 重建比 cold-start 与 no-history 都好，并可重复 | 短纠正监督中的上下文保留及 WAM 适配 | 把普通 burn-in 原理说成首次提出；只有关闭历史结果就称上下文重建有效 |
| RL 独立运行、对相同 BC 起点有稳定增益，且有等交互预算对照 | 局部奖励优化作为扩展，或有明确机制差异时作为主方法 | 拼接输出 actor/critic 就声称超越 RLT/HALO-WA |
| 只有 cylinder 少量成功视频，消融仍无明显收益 | 如实降低结论，考虑后续完善/其他合适发表形式 | 用标题/叙事掩盖实验不足 |

若证据支持第一条，我更建议的研究问题是：**如何用有限局部纠正，让 WAM 在不破坏已有行为的前提下恢复精细操作能力；在原生视频—动作接口适配是否优于通用参数更新？**

可用的论文组织：失败与短段上下文审计 → 原生 OVCR 适配方法/监督目标 → 恢复采集与匹配历史协议 → 主结果 → 数据来源、适配位置、历史条件三类分开的消融 → 成本/能力保留/失败边界。主图画清楚冻结路径、更新路径、历史是否参与，不把 reward/critic 画进尚未运行的系统。

建议最有价值的图表是：同任务各方法的完整/局部成功率；XY 偏差恢复区域图；在相同人工总时间下的数据效率曲线。Attention 热图只能作解释性补充，不能替代接口因果对照。

**是否值得投 ICRA：可以以 9 月 13 日的实测证据为决策点。** 如果至少有一个明确、可重复的核心增益，合理的强基线，最好有 cylinder 以外的任务支持，并能清楚界定与相关工作的区别，值得尝试。两个任务是本项目的建议，不是会议硬性数量要求。如果最后只是“重新采数据后普通 SFT 好了一点”，而接口方法没优势、历史因果也没验证，那么以新算法投稿的依据偏弱。不能仅靠再挂一个 RL 名称补足。尚未拿到论文具体贡献和完整实验表，无法给出可靠接收概率。

## 9. 根据用户补充：ego、加速、VLM 标注与 DPO 如何取舍

用户补充的已知结果是：cylinder 和 power-adapter 都做了 DAgger，但未见明显增益；cylinder 的原 SFT 较好。合作方的 ego 视频利用和推理加速尚无确定结果，暂不作为本轮核心结论。现有信息仍缺逐模型成功次数/测试总数，不能据此计算显著性或接收概率。

### 9.1 不需要等 DAgger baseline 成功才做下一步

如果拟议方法能在相同数据/预算下超过 SFT 与合理调好的 DAgger baseline，DAgger 的弱结果可以成为待解决问题的一部分。要确保 baseline 配方有效、memory 匹配、公平调参，并公开数据局限，不能故意保留不匹配的弱对照。

目前“首次把 DAgger 接到 WAM”即使事实成立，也不足以自动构成强方法贡献；还需要解释原生接口为什么适合学习纠正，并拿出跨任务的对照证据。如果 DAgger、OVCR 都没效果，单纯改名为 RL 不会增加证据。

### 9.2 打标签不是自动升级成 RL；DPO 有真实理论依据，但要准确命名

| 做法 | 实际学习机制 | 合适的描述 |
|---|---|---|
| VLM/人工选成功轨迹，再计算原 flow action loss | 改变 BC 的训练数据 | 成功筛选 BC / 数据整理 |
| VLM 分数作为非负 action loss 权重 | 加权回归；是否属于具体离线策略优化要看目标与推导 | reward-weighted BC，不自动等于 actor-critic |
| 根据偏好、参考策略和策略概率比优化 | 直接偏好优化，可与 KL 正则奖励最大化联系 | 离线偏好优化；实现符合相应方法时可解释为隐式奖励策略优化 |
| 学 return/value/advantage，再提取改进策略 | 离线或迭代批量 RL | 对应实际算法的离线/批量 RL |
| 新 rollout + reward + actor/critic 等策略改进 | 在线 RL | 报告真实交互预算与更新规则 |

[原始 DPO，NeurIPS 2023](https://papers.neurips.cc/paper_files/paper/2023/hash/a85b405ed65c6477a4fe8302b5e06ce7-Abstract-Conference.html) 在偏好模型与 KL 正则最优策略的关系下消去显式奖励模型。它不要求显式 critic，也不要求离线训练时重新采样环境。因此“没有 critic 就不是 RL 相关方法”过于绝对；但离线 DPO 结果不能描述成真机在线 RL。

有两类贴近机器人纠正的工作值得参考：

- [APO，NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/347110fb894281e5e937f6ccd998a6eb-Abstract-Conference.html)：利用接管交互的二元 desirability，处理机器人动作不可逆、难获得严格偏好对的问题，并针对离散动作 token 做自适应重加权。支持学习失败反馈；不能把离散 token 概率公式直接套到当前连续 flow action 上。
- [Preference Aligned Visuomotor Diffusion Policies，2026 预印本](https://arxiv.org/html/2602.09583v1)：在真实布料操作研究扩散策略偏好对齐，包括结合 RPO/KTO 的方法。说明机器人扩散策略偏好学习是已有研究方向；任务偏好与精密插入的成功优化不同，仍需本任务验证。

[Diffusion-DPO，CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Wallace_Diffusion_Model_Alignment_Using_Direct_Preference_Optimization_CVPR_2024_paper.html) 用扩散似然的下界构造偏好目标，原验证是图像生成。当前 AHA action 路径使用 flow/velocity 训练目标，不能把一个未加权 MSE 直接叫作精确的 `log π(a|o)`。若用参考模型的 flow loss 差构造偏好 surrogate，必须明确近似、核对时间权重及符号，并验证参考模型/偏好对/有效 action mask，而不是声称已原样复现 DPO。

最容易出错的是数据配对：接管前的 POLICY 动作和几秒后的 HUMAN 动作处于不同状态，不能不加处理地当作同一观测下的 winner/loser；一次最终失败也不意味着整条轨迹的每个动作都是负例。人的“向左纠正”只在相应右偏状态下为正例，放到左偏状态可能恰好错误。优先使用明确标注的局部错误与纠正，或采用有依据的非配对方法；不能把全部 POLICY/SYSTEM_HOLD 都标为坏动作。

VLM 更适合先辅助粗阶段、明显失败类型或终态标注。没有证据表明它仅凭现有图像能稳定判断毫米级同轴度、遮挡下的实际插入与接触力。对于当前两个任务和有限 rollout，人工标注成功/失败加“不确定”可能比新建 VLM 评价系统更可靠。若使用 VLM，应先在独立人工标注子集测混淆矩阵，允许拒判；正式真机评价不能只由同一个训练 reward model 自评。

### 9.3 RECAP 不是“混 demo 与 DAgger 再 SFT”而已

[π*0.6 / RECAP 原论文](https://www.pi.website/download/pistar06.pdf) 预测价值的分布（distributional value），从轨迹回报和价值估计获得 advantage，再做 advantage-conditioned policy extraction，并迭代收集交互。普通 D+H 混合 SFT 只是数据聚合基线，不是完整 RECAP。若要靠近这条路，需要完整 reward/terminal/时间对齐的数据、可靠 value、advantage 估计以及同数据 BC 对照；稀少短纠正段很难独立提供这些信息。

### 9.4 剩余时间的最终排序

先完成无历史 B0 与结构化 R 数据的普通微调，再跑一个 OVCR 代表组。若合作方在 9 月 12 日前交付可重复的推理加速，先单独测速并测试同 checkpoint 的成功率保持；对于插入，它可能通过减少观测延迟直接产生价值。若其实际成为主贡献，应以加速方法及成功率/延迟折中组织论文，而非把它当无关附赠。若 ego 视频方法届时已成熟，则固定其配方补有/无 ego 对照；几百条视频本身不构成迁移机制或有效性证明。

偏好优化可作为下一阶段选择，但当前没有证据认为它比采集新 R、普通微调和公平 OVCR 对照更值得占今晚的三张卡。只有已有可靠偏好标签和经过检查的 flow 偏好目标时，才把它作为独立 pilot；同数据 positive-only BC 必须保留，才能判断负反馈究竟有没有额外价值。

就当前描述而言，论文核心实证尚不充分。完成一条清楚的有效机制，比同时列出 ego、DAgger、DPO/RL、加速四个尚未验证的贡献更有机会形成可评审的论文。两种插入任务能支持精细插入范围内的结论，不足以直接外推所有 WAM 操作任务。
